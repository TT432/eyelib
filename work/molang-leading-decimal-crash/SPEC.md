# Molang 无前导零小数崩溃修复规格

## 问题模型

Eyelib 21.1.14 在实体动画生成 Bedrock 粒子时编译表达式 `.0 + math.cos(variable.particle_random_2 * 360) * 0.3`。手写 Molang tokenizer 仅在当前字符为数字时进入数字读取，因此把开头 `.` 识别为成员访问符，解析失败；异常从粒子组件解码逸出到实体渲染事件并终止客户端。

## 功能需求

- Molang tokenizer 必须把 `.` 后紧跟十进制数字的序列识别为数字字面量。
- `.0`、`.5`、`.5e-2`、`.5f` 必须通过解析。
- 崩溃报告中的完整表达式必须通过编译。
- `.` 未紧跟数字时仍必须保留为成员访问符，不改变 `variable.name` 等既有语法。

## 非功能需求

- 修复必须位于词法层，不得在粒子解码或渲染事件中吞掉编译异常。
- 不得重写或复制表达式字符串。
- 不得影响多版本源码生成；修改共享 `src/` 实现。

## 前置条件

- 输入是 Molang 表达式字符串。
- 数字读取仍使用 Java `Double.parseDouble` 支持的十进制、科学计数法和 `f/F` 尾缀现有路径。

## 后置条件

- 合法无前导零小数生成 `NumberLiteralExpr`，其 `rawText` 保留原文本。
- 完整粒子表达式进入绑定与字节码生成阶段，不再抛出 `ExpressionCompileException: Failed to parse`。

## 不变量

- 标识符成员访问中的点号仍生成 `DOT` token。
- 已支持的整数、有前导零小数、科学计数法及 `f/F` 尾缀行为保持不变。

## 异常行为

- 单独的 `.` 或点号后非数字仍按原语法处理，并由解析器在不合法上下文拒绝。
- 其他畸形数字不在本次修复范围内，不通过容错改写掩盖。

## 副作用

- 仅扩展 Molang 数字词法接受集合；无持久状态、I/O 或渲染状态副作用。

## 验证

1. 新增词法参数测试覆盖 `.0`、`.5`、`.5e-2`、`.5f`。
2. 新增编译回归测试覆盖崩溃报告中的完整表达式。
3. 先运行回归测试确认旧实现失败，再修复并运行定向测试。
4. 对 1.21.1 执行项目构建，确认目标崩溃版本源码可编译。
