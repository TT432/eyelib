# 变长 call 参数列表化（format v11）

> 状态：已实现（2026-08-09）。用户决策：变长参数「不应该是 argN，应该是
> argX[...]: {Type}[]，在节点里编辑对应的列表。完全消除 arg_count 这个字段」。

## 1. 需求

变长函数（`query.is_name_any` / `query.entity_biome_has_any_identifier` 等）的参数
不再以 `arg_count` 选项 + `argN` 端口组表达，改为节点内的字面值列表编辑器；
`arg_count` 字段从数据模型中完全消除。

## 2. 设计

### 2.1 数据模型

- `NodeOptionDef.OptionType.LIST`：值为 JSON 数组（字面值条目，行内字面值口径
  ——数字/布尔/字符串，同 ANY 端口行内编辑器）。
- `query.call` / `math.call` / `exec.call` 选项 = `function` + `args`（LIST）。
- 端口（`NodeTypes.callArgPorts`）：
  - 定长签名函数 → 仅固定前缀命名端口（id 恒 argN，label 带参数名/类型）；
  - 变长签名函数 → 只有固定前缀端口，**变长尾参进 args 列表**；
  - 未知函数（含零参内建——签名表只收录带参函数）→ 无 arg 端口。

### 2.2 编辑器

- 列表行标签：`MolangFunctionSignatures.variadicListLabel`——变长
  `ids[...]: str[]`（元素类型标注），未知 `args[...]`，定长不显示。
- 未知函数且列表为空时行隐藏（零参内建走未知分支，空列表隐藏避免噪声行）；
  有条目时显示（导入/旧数据携带的参数可见可编）。
- `EvmListConfigurator`：每行字面值文本框 + 删除键，底部 + 追加；条目编辑
  只写回不重建（重建丢焦点），增删行才重建。选项过桥形态是 JSON 数组文本
  （LDLib2 选项系统只载原始类型，`EvmValues` LIST ↔ String 互转，写回解析）。

### 2.3 发射

`EmitSession.emitCallLike`：先固定前缀端口值（argN 顺序），后追加 args 列表条目
（`MolangLiterals.literal` 口径；空串条目跳过——编辑器半成品行不发射）。
零参（无端口 + 空列表）保持属性访问形。

### 2.4 反编译

`MolangDecompiler.callNode`：定长签名 → argN 连线（同前）；变长/未知 → 字面量
实参（数字/字符串/true/false 标识符）进 args 数组；**非字面量实参跳过 + 诊断**
（内建变长函数实参语义上全是字面量，实机普查零出现）。调用参数 16 上限移除。

### 2.5 迁移 v10 → v11

- 所有 call 节点删 `arg_count`；
- 变长/未知函数的 argN（序号 > 固定前缀长）：常量与连线 const 值按序号升序
  收进 args 数组；连线源为非常量表达式 → 丢弃（无列表表达能力，实机普查零出现）；
- 仅喂被收端口的孤儿 const 节点删除；
- 定长函数只删 arg_count，固定前缀端口/常量不动。

## 3. 判据与等价性

- 变长参数在 v10 图里全部是「未接线 + 行内常量」（const 内联 pass 先行）或
  「连线 const」，两者都是字面量——列表化无损。
- 发射等价：同序同字面值口径 → molang 文本不变。

## 4. 前置 / 后置 / 不变量

- 前置：无（导入/迁移/编辑器全链路自带）。
- 后置：图中不存在 arg_count 选项；变长参数不以端口形态存在。
- 不变量：定长函数的端口/连线/常量语义不变；零参调用发射属性访问形不变。
- 异常行为：非字面量变长实参（仅理论可能）→ 反编译诊断 + 跳过；
  迁移期连线非常量表达式 → 丢弃（实机零出现）。

## 5. 非目标

- 列表条目不支持动态表达式（字面值编辑器定位，与 ANY 行内一致：
  动态值应当连线——而变长参数不再有端口，动态场景用定长函数或子图）；
- 列表不可连线（无列表类型生产者节点）。
